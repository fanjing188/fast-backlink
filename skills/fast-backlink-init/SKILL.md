# 初始化本地身份档案

用户说“初始化资料”“建立身份档案”“补齐投稿身份”时使用。完成标准是所有身份字段都在本地档案中存在；用户尚未提供的值仍为空，不把“键齐全”说成“事实齐全”。

## 找到本次使用的库

1. 找到用户指定的 Fast-Backlink 源码或安装目录，确认存在 `backlink_kit/onboarding.py`。把此目录作为命令工作目录 ROOT，使用 Python 3.11+。
2. 明确当前安装的 CONFIG 绝对路径；已有安装可先运行 `backlink-kit doctor` 核对安装范围。多个库时请用户选定，不默认采用另一个 Agent 或旧安装的资料。
3. 只用所选配置解析 `kits_dir`。不要输出整个配置、密钥或令牌。若安装版本没有 onboarding 模块，报告需要更新，不能假装命令已可用。

## 一次收齐信息

在 ROOT 工作目录执行，输出重定向到私有工作目录，权限设为 0600，不将已有身份内容直接贴进聊天：

```sh
python3 -m backlink_kit.onboarding --config "$CONFIG" profile-template > "$PRIVATE/profile.json"
```

字段全集以模板和 `backlink_kit/kits.py` 的 `PROFILE_KEYS` 为准，不在技能中另维护字段名单。已有值保留，只询问空值、矛盾值及用户要求修改的字段。

按下列四组引导，实际问题中逐个列出该组尚缺的字段名与中文含义，让用户一次回答一组或一次提交全部：

- 姓名与联系：投稿署名、名、姓、职位、联系邮箱。
- 团队与地区：公司或团队、国家、城市。
- 公开链接：模板内全部社交账号和个人网站；区分账号名与完整链接，不擅自拼成另一个账号。
- 头像与通用问答：头像来源或本地路径；只保存用户明确给出的共享答案，不要求收入、融资等非必要信息。

用户可回答“不适用”“暂不提供”；保存为 `""`，并把未提供字段列在结果中。不要从邮箱猜姓名，不从语言猜地区，不从产品页面猜公司。不收集密码、验证码、支付资料或密钥。没有回答不等于同意覆盖旧值。

## 保存并验证

将确认的答案写入私有 JSON：`{"fields":{"字段名":"答案"},"qa":{"问题":"已确认答案"}}`。字段值必须是字符串；不要用嵌套 `value` 对象。使用文件传参，不把个人信息放进 shell 参数或日志。

```sh
python3 -m backlink_kit.onboarding --config "$CONFIG" profile-save --file "$PRIVATE/answers.json"
```

该入口补齐全部 PROFILE_KEYS，合并已有身份、自定义字段和共享问答，保留未涉及的信息，并读回校验；只返回字段名与空字段名单，不回显值。档案为 `kits_dir/_profile.json`，文件权限 0600。

再按用户授权在素材库的“身份档案”查看已保存结果。纯文件校验不冒充扩展运行验证；保存身份不需要自动重启服务。若保存结果未知，先只读该档案核实，不盲目重复覆盖。

## 交付

只报告保存位置、字段总数、已填/空值字段名及需要用户补充的项。不粘贴完整身份信息，不把私有 JSON 放进源码、技能、公开包或个人记忆。不安装插件、不修改其他 Agent 的配置、不向外部表单提交。
